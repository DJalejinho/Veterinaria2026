##### Resaltar con JavaScript el elemento activo de la barra lateral

Si renderizas una sola vez la barra lateral y quieres resaltar rutas en el cliente:

```js
function setActiveSidebarItem(href) {
  document.querySelectorAll(".sidebar-menu .nav-link").forEach((el) => {
    el.classList.toggle("active", el.getAttribute("href") === href)
  })
}

// Ejecutar al cambiar de ruta
setActiveSidebarItem(window.location.pathname)
```

##### Selector de idioma conectado a una configuración regional real

La barra superior de demostración incluye un selector de idioma, pero el marcado por sí solo no cambia nada: la aplicación debe cambiar el idioma, y hacerlo mal es peor que no ofrecer la opción. El patrón siguiente cubre los aspectos esenciales de un selector.

```html
<li class="nav-item dropdown">
  <a class="nav-link" href="#" id="language-menu" data-bs-toggle="dropdown"
     aria-expanded="false" aria-label="Cambiar idioma; idioma actual: español">
    <i class="bi bi-translate" aria-hidden="true"></i>
  </a>
  <ul class="dropdown-menu dropdown-menu-end" aria-labelledby="language-menu">
    <li>
      <a class="dropdown-item active" href="/es/dashboard" hreflang="es" aria-current="true">
        Español <i class="bi bi-check-lg ms-2" aria-hidden="true"></i>
      </a>
    </li>
    <li><a class="dropdown-item" href="/en/dashboard" hreflang="en">Inglés</a></li>
    <li><a class="dropdown-item" href="/ar/dashboard" hreflang="ar">العربية</a></li>
  </ul>
</li>
```

Cuatro aspectos distinguen un selector funcional de uno meramente decorativo:

1. **Cada opción es un enlace real a la misma página en otro idioma**, no un `#` con un controlador de clics. Un enlace se puede guardar en marcadores, indexar, abrir en una pestaña nueva y funciona antes de que cargue JavaScript. Agrega `hreflang` para que las tecnologías de asistencia anuncien el cambio de idioma y los motores de búsqueda relacionen las URL.
2. **El idioma debe formar parte de la URL** (`/es/dashboard`) o de una cookie que lea el servidor; no de `localStorage`. El HTML renderizado en el servidor debe conocer el idioma *antes* de generarse; `localStorage` solo se puede leer después de que la página ya se haya enviado en el idioma incorrecto.
3. **Marca el idioma actual** con `.active` y `aria-current="true"`, y nómbralo en el `aria-label` del botón. Una bandera por sí sola no representa un idioma: varios idiomas comparten bandera y varios países comparten idioma.
4. **Para cambiar a un idioma RTL se necesita la hoja de estilos RTL**, además del atributo `dir`. Sirve `adminlte.rtl.css` y establece `<html lang="ar" dir="rtl">`; consulta [Compatibilidad con RTL](rtl.html).

Si el idioma está en la URL, el servidor selecciona la hoja de estilos y el selector se mantiene como marcado simple:

```html
<!-- Se genera en cada solicitud según el idioma activo -->
<html lang="ar" dir="rtl">
  <link rel="stylesheet" href="/css/adminlte.rtl.css">
```

En una aplicación renderizada en el cliente, haz lo mismo desde el router: cambia el idioma, vuelve a renderizar y actualiza la hoja de estilos `href` — en lugar de traducir directamente los nodos de texto.

##### Responder a los cambios del diseño y la barra lateral

Escucha los eventos de los complementos para coordinar tu código; por ejemplo, vuelve a ajustar un gráfico cuando se contraiga la barra lateral, para que mida de nuevo el ancho de su contenedor:

```js
let chart = /* instancia de ApexCharts */

document.addEventListener("collapse.lte.push-menu", () => {
  // esperar a que termine la transición (unos 300 ms de forma predeterminada)
  setTimeout(() => chart.updateOptions({}), 350)
})

document.addEventListener("open.lte.push-menu", () => {
  setTimeout(() => chart.updateOptions({}), 350)
})
```

El mismo patrón funciona con Tabulator, FullCalendar y cualquier biblioteca que lea el ancho de su contenedor al inicializarse.

##### Cargar contenido en una tarjeta mediante `fetch()`

```html
<div class="card" id="users-card">
  <div class="card-header">
    <h3 class="card-title">Usuarios</h3>
    <div class="card-tools">
      <span class="spinner-border spinner-border-sm text-secondary d-none" id="users-spinner" role="status"></span>
    </div>
  </div>
  <div class="card-body p-0">
    <div id="users-body" class="text-secondary p-3">Cargando&hellip;</div>
  </div>
</div>

<script>
  const spinner = document.getElementById("users-spinner")
  const body = document.getElementById("users-body")

  spinner.classList.remove("d-none")
  fetch("/api/users")
    .then((r) => r.text())
    .then((html) => { body.innerHTML = html })
    .catch(() => { body.textContent = "No se pudo cargar." })
    .finally(() => spinner.classList.add("d-none"))
</script>
```

##### Gráficos que se adaptan al modo oscuro

Las bibliotecas de gráficos dibujan su propio texto e información sobre herramientas, así que no conocen `data-bs-theme`. ApexCharts, por ejemplo, muestra una ayuda clara y etiquetas de eje gris oscuro de forma predeterminada. En una tarjeta oscura, el color heredado de la ayuda queda casi blanco sobre blanco y no se lee. La biblioteca ofrece un tema oscuro; indícale cuál usar y actualízalo cuando cambie el modo.

Todas las páginas de demostración incluyen este helper en los scripts compartidos al pie de la página. Establece el valor global predeterminado de `theme.mode` de ApexCharts según `<html data-bs-theme>` **antes** de crear los gráficos, mantiene transparente el fondo del gráfico (el modo oscuro lo volvería gris) y observa el atributo para que cada gráfico con `chart.id` responda al selector, a la preferencia del sistema en modo automático o a tu propio código:

```html
<script>
  const mode = () => (document.documentElement.getAttribute("data-bs-theme") === "dark" ? "dark" : "light")
  globalThis.Apex ||= {}                                   // objeto de opciones globales de ApexCharts
  Apex.theme = { mode: mode() }
  Apex.chart = Object.assign(Apex.chart || {}, { background: "transparent" })
  new MutationObserver(() => {
    const next = mode()
    Apex.theme = { mode: next }
    for (const { chart } of Apex._chartInstances || []) {
      chart.updateOptions({ theme: { mode: next } }, false, false)
    }
  }).observe(document.documentElement, { attributes: true, attributeFilter: ["data-bs-theme"] })
</script>
<script src="https://cdn.jsdelivr.net/npm/apexcharts@3.37.1/dist/apexcharts.min.js"></script>
```

Asigna un `id` a cada gráfico para que se registre y reciba las actualizaciones:

```js
new ApexCharts(document.querySelector("#revenue-chart"), {
  chart: { id: "revenue-chart", type: "area", height: 300 },
  // …
}).render()
```

Si prefieres el evento de ColorMode al observador del atributo, `document.addEventListener("changed.lte.color-mode", e => …)` recibe `e.detail.resolved` (`"light"` o `"dark"`). El observador también detecta cambios en la preferencia del sistema en modo automático y cualquier código que modifique directamente el atributo. La misma idea se aplica a otras bibliotecas: Chart.js lee `Chart.defaults.color` y `Chart.defaults.borderColor`; puedes obtener esos valores con `getComputedStyle(document.body)` y volver a aplicarlos mediante `chart.update()` en el mismo observador.

##### Imprimir una página como documento

Una página impresa es un documento, no una captura de la aplicación. Por eso AdminLTE omite el marco —encabezado, menú lateral y pie de página— y utiliza todo el ancho de la hoja para el contenido. El contenido se prepara para leerse en papel: se imprime la dirección de los enlaces externos, los botones conservan un contorno y todo aparece en negro sobre blanco para ahorrar tinta.

En las páginas que se imprimen como *documentos* —una factura, un presupuesto, una orden de trabajo o un comprobante para un cliente—, esos dos detalles pueden resultar inconvenientes. No hace falta que aparezca `Pagar en línea (https://pay.example.com/inv/12345?token=…)` en una factura impresa ni que los botones queden enmarcados. Agrega `data-lte-print="plain"` a `<html>`, `<body>` o a cualquier contenedor para ocultarlos y mantener el texto negro sobre fondo blanco:

```html
<html lang="es" data-lte-print="plain">
```

Limita el atributo a una parte de la página cuando solo esa parte sea el documento:

```html
<div class="card" data-lte-print="plain">…la factura…</div>
```

Si la página siempre se imprime como documento, establece el atributo al iniciar la impresión:

```js
document.querySelector("#print-invoice").addEventListener("click", () => {
  document.documentElement.setAttribute("data-lte-print", "plain")
  window.print()
})
```

Para imprimir una copia de la pantalla con el menú y todo el marco de la aplicación, agrega `data-lte-print="app"` a `<html>` o `<body>`:

```html
<html lang="es" data-lte-print="app">
```

Para mostrar solo una parte del marco, usa las utilidades de visualización de Bootstrap: `.d-print-flex` para el encabezado (una barra de navegación) y `.d-print-block` para la barra lateral o el pie de página:

```html
<aside class="app-sidebar bg-body-secondary shadow d-print-block" data-bs-theme="dark">…</aside>
```

`.d-print-none` oculta en ambos modos cualquier elemento que no quieras imprimir, como una barra de botones encima de la factura.
