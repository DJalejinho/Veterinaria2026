AdminLTE es una plantilla estática de HTML/CSS/JS; implementarla no requiere nada fuera de lo común. Sin embargo, algunas decisiones pueden afectar significativamente el peso de la página, el tiempo hasta que sea interactiva y la fiabilidad de la CDN. Esta página explica cuáles conviene configurar correctamente.

##### Qué publicar

El artefacto que debes publicar incluye todo lo que está dentro de `dist/`, además de tu propio HTML o de las plantillas renderizadas en el servidor:

```text
dist/
├── css/                ← stylesheets (LTR + RTL, dev + minified)
│   ├── adminlte.css
│   ├── adminlte.min.css
│   ├── adminlte.rtl.css
│   └── adminlte.rtl.min.css
├── js/                 ← JavaScript bundle (dev + minified)
│   ├── adminlte.js
│   └── adminlte.min.js
└── assets/             ← imágenes y fuentes de demostración (reemplázalas por las tuyas)
```

Si integras AdminLTE en tu aplicación, no publiques `src/`, `node_modules/` ni el HTML de demostración.

##### Usa siempre las versiones `.min` en producción

Las versiones minificadas contienen el mismo código, pero sin espacios innecesarios y con identificadores acortados. `adminlte.css` reduce el tamaño aproximadamente entre un 15 y un 20 %; `adminlte.js`, cerca de un 30 % después de gzip. Los archivos sin minificar sirven durante el desarrollo para depurar con mapas de código legibles; nunca los publiques para los usuarios.

| Recurso | Desarrollo | Producción |
|---|---|---|
| Stylesheet | `dist/css/adminlte.css` | **`dist/css/adminlte.min.css`** |
| Script | `dist/js/adminlte.js` | **`dist/js/adminlte.min.js`** |
| RTL stylesheet | `dist/css/adminlte.rtl.css` | **`dist/css/adminlte.rtl.min.css`** |
| Select2 theme *(optional)* | `dist/css/adminlte-select2.css` | **`dist/css/adminlte-select2.min.css`** |

`adminlte-select2.css` es opcional y solo hace falta si tu aplicación carga [Select2](integrations.html#select2-compatibility-theme); no forma parte de `adminlte.css`. `adminlte-docs.css` solo aplica estilos a las páginas de documentación: no lo publiques.

##### Compresión en el servidor perimetral

Configura el servidor web o la CDN para comprimir con gzip o Brotli las respuestas de estos tipos de contenido:

```nginx
# nginx
gzip on;
gzip_types text/css application/javascript text/html image/svg+xml;
gzip_comp_level 6;
```

```apache
# Apache
AddOutputFilterByType DEFLATE text/css application/javascript text/html image/svg+xml
```

Cloudflare, Vercel, Netlify y la mayoría de los servicios de alojamiento administrado lo hacen automáticamente. Compruébalo con `curl -I -H "Accept-Encoding: gzip" your-page-url` y verifica que la respuesta incluya `content-encoding: gzip`.

##### Encabezados de caché

Los artefactos de `dist` solo incluyen hashes de contenido en sus nombres *si configuras esa función en tu empaquetador*; AdminLTE usa nombres de archivo fijos. Hay dos estrategias habituales:

1. **Caché corta y parámetro de versión en la URL** (simple, no necesita un proceso de compilación):

   ```html
   <link rel="stylesheet" href="/dist/css/adminlte.min.css?v=4.0.0" />
   <script src="/dist/js/adminlte.min.js?v=4.0.0"></script>
   ```

   Configura `Cache-Control: public, max-age=86400` (1 día) en el servidor. Cambia `?v=` en cada versión para invalidar la caché.

2. **Nombres de archivo con hash** (para producción; requiere un empaquetador):

   Configura el empaquetador para generar `adminlte.[hash].min.css` y usa ese nombre en tu HTML. Establece `Cache-Control: public, max-age=31536000, immutable` (1 año). Vite, Webpack y Rollup lo hacen de forma predeterminada cuando importas AdminLTE.

##### Hashes de integridad de CDN

Si cargas AdminLTE desde una CDN pública (jsDelivr, unpkg), incluye un hash de Subresource Integrity (SRI) para impedir que una CDN comprometida sirva JavaScript malicioso sin que lo notes:

```html
<link
  rel="stylesheet"
  href="https://cdn.jsdelivr.net/npm/admin-lte@4.9.1/dist/css/adminlte.min.css"
  integrity="sha384-PASTE_THE_HASH_HERE"
  crossorigin="anonymous"
/>
```

Puedes obtener el hash en la [página de detalles de archivos de jsDelivr](https://www.jsdelivr.com/package/npm/admin-lte): abre cualquier archivo y copia la línea «SRI». Haz lo mismo con Bootstrap, Popper, OverlayScrollbars y Bootstrap Icons.

Si alojas los recursos en un servidor privado, genera el hash tú mismo:

```bash
openssl dgst -sha384 -binary dist/css/adminlte.min.css | openssl base64 -A
```

##### El orden de carga importa

Respeta el orden de los scripts para evitar errores que no se muestran claramente:

```html
<head>
  <!-- 1. Bootstrap Icons (CSS de la fuente); cargar primero para que los iconos aparezcan con la página -->
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap-icons@1.13.1/font/bootstrap-icons.min.css" />

  <!-- 2. OverlayScrollbars (opcional, para el desplazamiento de la barra lateral) -->
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/overlayscrollbars@2.11.0/styles/overlayscrollbars.min.css" />

  <!-- 3. AdminLTE; incluye Bootstrap CSS mediante sus importaciones -->
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/admin-lte@4.9.1/dist/css/adminlte.min.css" />
</head>

<body>
  …

  <!-- Scripts al FINAL de body -->
  <!-- 4. Popper (dependencia de Bootstrap para menús, ayudas emergentes y ventanas emergentes) -->
  <script src="https://cdn.jsdelivr.net/npm/@popperjs/core@2.11.8/dist/umd/popper.min.js"></script>

  <!-- 5. Bootstrap -->
  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.min.js"></script>

  <!-- 6. OverlayScrollbars -->
  <script src="https://cdn.jsdelivr.net/npm/overlayscrollbars@2.11.0/browser/overlayscrollbars.browser.es6.min.js"></script>

  <!-- 7. AdminLTE; debe cargarse DESPUÉS de Bootstrap -->
  <script src="https://cdn.jsdelivr.net/npm/admin-lte@4.9.1/dist/js/adminlte.min.js"></script>
</body>
```

##### ¿Defer o async?

El paquete de AdminLTE espera a `DOMContentLoaded` antes de conectar su API de datos, así que se recomienda usar `defer`:

```html
<script defer src="/dist/js/adminlte.min.js"></script>
```

No uses `async`: el script podría ejecutarse antes de que se analicen sus dependencias (Bootstrap y Popper), y los controladores se asociarían a elementos que todavía no existen.

##### CSS crítico

Para mostrar el contenido inicial en menos de un segundo, incluye en línea los estilos del contenido visible sin desplazarse (encabezado, marca y contenido inicial) y carga el resto de `adminlte.min.css` de forma asíncrona:

```html
<style>/* CSS crítico extraído para /dashboard */</style>

<link
  rel="preload"
  as="style"
  href="/dist/css/adminlte.min.css"
  onload="this.onload=null;this.rel='stylesheet'"
/>
<noscript><link rel="stylesheet" href="/dist/css/adminlte.min.css" /></noscript>
```

Extrae el CSS crítico durante la compilación con herramientas como [Critters](https://github.com/GoogleChromeLabs/critters) o [Penthouse](https://github.com/pocketjoso/penthouse). En paneles protegidos por inicio de sesión —donde la velocidad de la primera carga importa menos que en una página de marketing—, normalmente no hace falta.

##### Precargar recursos clave

Envía los recursos críticos al navegador antes de que los encuentre en el HTML:

```html
<link rel="preload" as="style" href="/dist/css/adminlte.min.css" />
<link rel="preload" as="font" href="/fonts/source-sans-3.woff2" type="font/woff2" crossorigin />
<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin />
```

Precarga únicamente los recursos que se usan en todas las páginas. Precargar en un diseño compartido recursos exclusivos de una ruta consume ancho de banda innecesariamente.

##### Carga diferida de subpáginas

Si tu panel tiene muchas rutas y el servidor genera HTML para cada una, conviene importar CSS por ruta en vez de usar una hoja de estilos enorme. El CSS principal de AdminLTE es pequeño (unos 44 KB con gzip), pero los estilos específicos de gráficos, calendarios y tablas pueden acumularse; cárgalos solo donde hagan falta.

En las SPA, divide el código de las integraciones pesadas:

```js
// No incluir la aplicación de calendario en el paquete principal
const Calendar = () => import("./Calendar.vue")
```

##### Límite de tamaño del paquete

Estos son los tamaños comprimidos con gzip de los artefactos publicados actualmente en `dist/`:

| Recurso | Tamaño (gzip) |
|---|---|
| `adminlte.min.css` | ~40 KB |
| `adminlte.rtl.min.css` | ~40 KB |
| `adminlte.min.js` | ~5 KB |

La carga completa de la primera página (HTML, Bootstrap, AdminLTE, Bootstrap Icons, Popper y OverlayScrollbars) ocupa aproximadamente **180 KB con gzip** al usar una CDN. La compilación de CI ejecuta `bundlewatch` y falla si algún recurso supera su límite.

##### Service workers y compatibilidad sin conexión

AdminLTE solo contiene archivos estáticos, así que puedes almacenarlos en la caché de un service worker sin cambios. Esta es una configuración mínima de Workbox:

```js
import { precacheAndRoute } from "workbox-precaching"

precacheAndRoute([
  { url: "/dist/css/adminlte.min.css", revision: "4.0.0" },
  { url: "/dist/js/adminlte.min.js", revision: "4.0.0" },
  // ...tus propias páginas
])
```

##### Quitar archivos de desarrollo antes de publicar

Si publicas directamente la carpeta de demostración `dist/`, excluye estos patrones de la carga:

- `*.map` (mapas de código fuente; revelan el código a quienes abran las herramientas de desarrollo).
- `**/html/` (compilación intermedia de Astro, si existe).
- `**/.astro/` (caché de Astro).

For `rclone` / `rsync`:

```bash
rsync -avz --delete \
  --exclude='*.map' \
  --exclude='html/' \
  --exclude='.astro/' \
  dist/ user@server:/var/www/your-app/
```

##### Nota sobre la caché de Cloudflare

El TTL predeterminado de la caché del navegador de Cloudflare es de 4 horas. Si publicas una nueva versión y quieres que los usuarios la vean enseguida, [purga las rutas afectadas](https://developers.cloudflare.com/cache/how-to/purge-cache/) desde el panel o la API de Cloudflare. De lo contrario, quienes tengan las páginas en caché podrían seguir viendo el CSS/JS anterior durante un máximo de cuatro horas.
